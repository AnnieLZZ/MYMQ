规则 1：强迫架构规划（对接 Architect 工具）
规则内容：

在开始编写复杂的 C++ 代码、处理系统级任务或进行架构设计前，必须优先调用 ask_local_architect 函数分析需求。

严格按照该工具返回的 JSON 中的 sub_tasks 步骤执行代码编写。

绝对遵守工具返回的 constraints 约束列表（例如：不要为了不可能的场景写防御代码、不私自重构无关代码等）。

不要自行发散或猜测，一切以本地架构师的输出要求为最高准则。

规则 2：反惰性审查机制（对接 Supervisor 工具）
规则内容：

在你声称“代码修改完成”或“逻辑正确”之前，必须调用 ask_local_supervisor 函数提交你的执行结果。

如果审查官返回 REJECTED 或 PENDING_VERIFICATION，你必须无条件执行其 required_actions 中要求的验证步骤（如写测试用例、运行验证）。

绝不允许用“看起来没问题”或“逻辑上应该是对的”来敷衍。没有经过该工具验证通过的代码，不许向我汇报完成。
